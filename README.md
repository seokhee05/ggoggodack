# 암레스트 실시간 검사 시스템

고정된 공장 카메라 영상을 항상 표시하고, 바코드 스캔을 기준으로 제품별 영상
녹화와 검사 행동 판정을 동시에 수행하는 Windows용 프로토타입입니다.

## 운영 흐름

```text
프로그램 실행 → 카메라 상시 표시 → 바코드 스캔
→ 제품별 영상 녹화 + 실시간 검사
→ 순서 오류·검사 지연 경고
→ 7개 검사 완료 시 영상과 결과 자동 저장
→ 다음 바코드 대기
```

작업자는 ROI 사각형을 지정하거나 `C`, `Q` 키를 누르지 않습니다.

## 검사 체크리스트

1. Knob 작동 이상 확인
2. Hinge 작동 이상 확인
3. Screw 외관·누락 확인 — 2Point, Driver 사용
4. Damper 누락 확인 — 2Point
5. Rib 파손 조각 확인 — 흔들기 동작
6. Knob·Hinge 굽힘/펴기 확인
7. Lining–Skin Ass’y Gap 확인

별도 마이크를 사용하지 않으므로 소리 자체를 판정하지 않습니다. 소리 확인이 필요한
항목은 흔들기와 굽힘·펴기 행동을 수행했는지 확인하는 방식으로 대체합니다.

## 현재 판정 방식

- MediaPipe Hand Landmarker가 손을 인식하면 손 중심 좌표를 우선 사용합니다.
- 장갑 등으로 손 인식이 실패하면 프레임 간 움직임을 이용한 보조 추적을 사용합니다.
- 화면의 노란 원은 현재 추적 중인 손 또는 작업 움직임 위치입니다.
- 최근 손·움직임 궤적의 이동 범위, 방향 전환, 양손 거리 변화를 계산합니다.
- Screw 단계는 영상에서 감지된 주황색 Driver 신호를 함께 사용합니다.
- 2Point 항목은 분리된 두 번의 행동 신호가 있어야 완료됩니다.
- 현재 단계가 아닌데 강한 Driver 신호가 감지되면 순서 오류를 경고합니다.
- 한 단계가 18초 이상 진행되지 않으면 빨간 화면 문구와 경고음으로 누락 가능성을 알립니다.
- 7개 항목이 모두 완료되면 영상과 JSON 결과를 자동 저장합니다.

> **중요:** 현재 프로그램은 작업자가 검사 행동을 수행했는지 추정하는
> 프로토타입입니다. 암레스트의 실제 파손, Gap 수치, Screw 체결 상태 등 제품
> 자체의 양불량을 판정하지 않습니다. 또한 실제 검사 동작으로 학습된 행동 인식
> 모델이 아니므로 오인식할 수 있습니다. 현장 정상·누락·순서 오류 영상을 충분히
> 수집한 뒤 임계값 조정과 정확도 검증이 필요합니다.

## Windows 설치

프로젝트 폴더에서 최초 한 번 `setup.bat`을 실행합니다.

```bat
setup.bat
```

설치 항목:

- Python 3.11
- Git
- Visual Studio Code
- Python 가상환경 `.venv`
- OpenCV
- MediaPipe
- Pillow

## 실행

`run.bat`을 실행하거나 다음 명령을 사용합니다.

```bat
.venv\Scripts\python.exe factory_app.py
```

프로그램이 실행되면 카메라 화면이 항상 표시됩니다. 바코드 입력란에 직접 입력하거나
USB 바코드 스캐너로 스캔한 뒤 `Enter`를 누르면 녹화와 실시간 검사가 시작됩니다.
USB 바코드 스캐너는 키보드 입력 방식이며, 스캔 후 `Enter`를 전송하도록 설정되어야
합니다.

검사 진행 중 다른 바코드가 입력되면 현재 검사를 NG로 저장할지 확인한 뒤 다음 제품
검사를 시작합니다. `현재 박스 강제 종료`를 누르면 완료되지 않은 항목은 `MISSING`,
최종 결과는 `NG`로 저장됩니다.

## 저장 영상 검사

화면 아래의 `저장 영상 검사` 버튼을 누르면 이미 촬영한 MP4·AVI·MOV·MKV 영상을
선택할 수 있습니다. 이어서 해당 영상의 바코드 또는 제품 번호를 입력하면 영상의
재생 시간을 기준으로 7단계 행동 검사를 수행합니다.

- 원본 영상은 수정하거나 복사하지 않습니다.
- 분석 중 `Esc`를 누르면 중단하고 현재까지의 결과를 NG로 저장합니다.
- 결과는 `results/제품번호_saved_result.json`에 저장됩니다.
- 같은 제품 번호의 결과가 이미 있으면 날짜와 시간이 파일명에 추가됩니다.

## 저장 파일

실시간 검사에서 바코드가 `ABC123`이면 다음 파일이 생성됩니다.

```text
recordings/ABC123.mp4
results/ABC123_result.json
```

동일한 바코드가 다시 입력되면 기존 파일을 덮어쓰지 않도록 날짜와 시간이 붙습니다.

결과 JSON에는 다음 항목이 저장됩니다.

- 바코드 또는 제품 번호
- 검사 시작·종료 시각
- 총 검사 시간
- 7개 항목별 `PASS` 또는 `MISSING`
- 항목별 감지 횟수와 완료 시점
- 순서 오류 및 누락 가능성 경고 내역
- 최종 `PASS` 또는 `NG`
- 검사 영상 경로

## 파일 구조

```text
ggoggodack/
├── factory_app.py          # 카메라·바코드·GUI·실시간 영상 저장
├── inspection_engine.py    # 7개 검사 순서 및 행동 판정 엔진
├── motion_tracker.py       # 손 인식 실패 시 작업 움직임 보조 추적
├── saved_video_check.py    # 저장 영상 선택·재생·분석
├── requirements.txt        # Python 패키지 목록
├── setup.bat               # 최초 설치
├── run.bat                 # 프로그램 실행
├── README.md
├── models/                 # MediaPipe 모델(최초 실행 시 생성)
├── recordings/             # 실시간 검사 녹화 영상
└── results/                # 실시간·저장 영상 검사 JSON 결과
```

`.venv`, `models`, `recordings`, `results`의 실행·생성 파일은 Git에 올리지 않습니다.

## 기본 설정

카메라 설정은 `factory_app.py` 상단에 있습니다.

```python
CAMERA_INDEX = 0
FRAME_WIDTH = 1280
FRAME_HEIGHT = 720
```

다른 카메라가 열리면 `CAMERA_INDEX`를 `1`, `2` 순서로 변경합니다.

현재 검사 기준 시간은 `factory_app.py`와 `saved_video_check.py`에서 엔진을 생성할 때
설정합니다.

```python
InspectionEngine(nominal_seconds=70.0, warning_seconds=18.0)
```

- `nominal_seconds`: 일반적인 전체 검사 시간의 참고값
- `warning_seconds`: 현재 단계에서 진전이 없을 때 누락 가능성을 경고하는 시간

개별 행동 감지 임계값은 `inspection_engine.py`의 `ActionRecognizer.detect()`에
있습니다. 현장 검증 없이 임계값을 임의로 낮추면 작업하지 않은 동작도 완료로
오인할 수 있으므로, 검사 영상을 비교하면서 조정해야 합니다.

## 현장 검증 시 확인 사항

1. 바코드와 저장 영상·JSON 파일명이 일치하는지 확인합니다.
2. 정상 검사에서 `0/7`부터 `7/7`까지 실제 순서대로 진행되는지 확인합니다.
3. 각 단계를 의도적으로 생략하여 18초 이후 경고가 표시되는지 확인합니다.
4. 순서를 바꾸거나 Driver를 먼저 사용했을 때 경고가 기록되는지 확인합니다.
5. 아무 작업도 하지 않을 때 단계가 자동으로 통과하지 않는지 확인합니다.
6. 조명, 작업복, 장갑, 카메라 위치가 달라져도 결과가 유지되는지 확인합니다.

프로토타입 결과만으로 생산 품질을 자동 판정하지 말고, 충분한 현장 검증 후
보조 검사 수단으로 사용해야 합니다.
