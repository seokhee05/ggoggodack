# 암레스트 실시간 검사 시스템

고정된 공장 카메라 영상을 상시 표시하고, 바코드 스캔을 기준으로 작업 영상을 녹화하면서 검사 행동을 동시에 확인하는 Windows용 프로토타입입니다.

이미 촬영된 영상을 선택하여 작업 과정을 다시 분석하는 기능도 제공합니다.

> 현재 프로그램은 작업자가 정해진 검사 행동과 작업 절차를 수행했는지 확인합니다. 제품의 실제 파손, 부품 누락, 나사 체결 상태 또는 치수 이상을 직접 판별하지 않습니다.

## 주요 기능

- 공장 카메라 영상 실시간 표시
- 바코드 스캔 또는 직접 입력을 통한 검사 시작
- 작업 영상 녹화와 검사 행동 분석 동시 수행
- 작업자의 손, 팔, 손목 움직임 추적
- 박스 개봉부터 제품 3개 검사, 박스 마감까지 총 17단계 확인
- 검사 단계별 완료 여부 표시
- 현재 검사 단계가 일정 시간 확인되지 않으면 경고
- 검사 영상 및 JSON 결과 자동 저장
- 저장된 영상에 대한 별도 사후 검사 지원

## 검사 방식

### 실시간 검사

`run.bat` 또는 `factory_app.py`를 실행하면 카메라 영상을 보면서 실시간 검사를 진행합니다.

```text
프로그램 실행
→ 카메라 영상 상시 표시
→ 바코드 스캔 또는 직접 입력
→ 검사 시작
→ 영상 녹화와 검사 행동 분석 동시 진행
→ 단계별 진행 상황 및 지연 경고 표시
→ 전체 검사 완료 시 영상과 결과 저장
→ 다음 바코드 대기
```

영상 촬영을 모두 마친 후 검사하는 방식이 아니라, 카메라에서 들어오는 각 프레임을 분석하면서 동시에 영상을 저장합니다.

작업자가 검사 영역을 직접 지정하거나 별도의 키를 눌러 ROI를 설정할 필요는 없습니다.

### 저장된 영상 검사

`run_saved_video.bat` 또는 `saved_video_check.py`를 실행하면 이미 촬영된 영상을 선택하여 검사할 수 있습니다.

```text
저장 영상 검사 실행
→ 검사할 영상 파일 선택
→ 바코드 또는 제품 번호 입력
→ 영상 재생과 검사 행동 분석
→ 단계별 결과 확인
→ JSON 결과 저장
```

실시간 검사와 저장 영상 검사는 같은 검사 엔진을 사용하지만, 입력 영상의 출처가 다릅니다.

- 실시간 검사: 현재 연결된 카메라 영상
- 저장 영상 검사: 이미 촬영된 영상 파일

## 검사 체크리스트

현재 코드는 박스 1개에 제품 3개가 들어 있다고 가정하며, 총 17단계의 작업 순서를 확인합니다.

### 준비 단계

1. 박스 덮개와 보호망 열기

### 제품 1 검사

2. 제품 1을 들어 올려 외관 및 흔들림 확인
3. 제품 1의 Driver Screw 2Point 확인
4. 제품 1을 뒤집어 Knob 및 Hinge 작동 확인
5. 제품 1의 Damper, Rib, 이음부 및 Gap 확인
6. 제품 1을 포장한 후 박스에 반환

### 제품 2 검사

7. 제품 2를 들어 올려 외관 및 흔들림 확인
8. 제품 2의 Driver Screw 2Point 확인
9. 제품 2를 뒤집어 Knob 및 Hinge 작동 확인
10. 제품 2의 Damper, Rib, 이음부 및 Gap 확인
11. 제품 2를 포장한 후 박스에 반환

### 제품 3 검사

12. 제품 3을 들어 올려 외관 및 흔들림 확인
13. 제품 3의 Driver Screw 2Point 확인
14. 제품 3을 뒤집어 Knob 및 Hinge 작동 확인
15. 제품 3의 Damper, Rib, 이음부 및 Gap 확인
16. 제품 3을 포장한 후 박스에 반환

### 마무리 단계

17. 보호망과 박스 덮개 닫기

전체 작업 흐름은 다음과 같습니다.

```text
박스 열기
→ 제품 1 검사 5단계
→ 제품 2 검사 5단계
→ 제품 3 검사 5단계
→ 박스 닫기
```

> 체크리스트의 `Screw`, `Damper`, `Rib`, `Gap` 등의 명칭은 해당 부위를 확인하는 작업 행동을 뜻합니다. 실제 부품 상태나 불량 여부를 직접 판정한다는 의미는 아닙니다.

## 현재 판정 방식

- MediaPipe Hand Landmarker로 작업자의 손을 인식합니다.
- MediaPipe Pose Landmarker로 팔과 손목 위치를 추가로 확인합니다.
- 손 인식이 부족할 경우 손목 위치와 프레임 간 움직임을 이용하여 보완합니다.
- 최근 작업 움직임에서 손 이동량, 이동 범위, 양손 간 거리 변화 등을 계산합니다.
- 제품을 들어 올리거나 뒤집는 행동은 손의 이동 범위와 움직임을 기준으로 추정합니다.
- 양손 조작 행동은 양손의 위치 변화와 거리 변화를 기준으로 추정합니다.
- Driver 사용 행동은 영상에서 감지되는 주황색 계열 물체와 움직임을 함께 확인합니다.
- Driver Screw 단계는 구분되는 행동 신호가 2회 확인되어야 완료됩니다.
- 현재 단계가 약 18초 동안 확인되지 않으면 누락 또는 지연 가능성을 경고합니다.
- 전체 17단계가 확인되면 영상과 결과를 저장합니다.

화면에 표시되는 점이나 선은 손, 손목, 팔 또는 작업 움직임을 추적하는 시각적 표시입니다.

저장 영상 검사에서는 암레스트 제품 후보 영역을 추가로 표시하지만, 이 영역은 시각적 보조 정보이며 제품의 실제 불량 판정에는 사용되지 않습니다.

## 판정 한계

현재 시스템은 작업자가 검사 행동을 수행했는지 추정하는 프로토타입입니다.

다음 항목은 직접 판별하지 않습니다.

- 실제 나사 누락
- 실제 나사 체결 불량
- Damper 부품 누락
- Rib 파손 여부
- Gap의 실제 수치
- 제품 균열 또는 외관 불량
- 실제 작동 소음 이상
- 검사 도구의 정확한 접촉 위치
- 작업자가 확인한 부위의 정확한 상태

별도 마이크를 사용하지 않으므로 소리 자체를 분석하지 않습니다.

또한 현재 코드는 작업자가 수행한 모든 행동을 독립적으로 분류하여 순서 위반을 즉시 판정하지 않습니다. 정해진 현재 단계에 해당하는 행동이 확인되지 않으면 일정 시간 이후 경고하는 방식입니다.

따라서 순서가 바뀌거나 다른 행동을 수행하더라도 이를 항상 정확히 구분하는 것은 아닙니다.

조명, 장갑, 작업복, 카메라 위치, 제품 색상, 도구 색상 등에 따라 오인식이 발생할 수 있습니다.

현장 적용 전 정상 작업 영상과 누락 작업 영상을 충분히 수집하고, 감지 기준과 경고 시간을 조정해야 합니다.

## Windows 설치

프로젝트 폴더에서 최초 한 번 `setup.bat`을 실행합니다.

```bat
setup.bat
```

프로그램 실행에는 Python 가상환경과 다음 패키지가 필요합니다.

```text
mediapipe
opencv-python
pillow
```

프로젝트의 `requirements.txt`에도 필요한 패키지 목록이 포함되어 있습니다.

```bat
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

MediaPipe 모델 파일은 다음 위치에서 사용합니다.

```text
models/hand_landmarker.task
models/pose_landmarker_lite.task
```

모델 파일이 없으면 프로그램 실행 시 다운로드를 시도합니다.

## 실시간 검사 실행

프로젝트 폴더에서 다음 파일을 실행합니다.

```bat
run.bat
```

또는 가상환경의 Python을 직접 실행합니다.

```bat
.venv\Scripts\python.exe factory_app.py
```

프로그램을 실행하면 카메라 화면이 표시됩니다.

바코드 입력란에 제품 번호를 직접 입력하거나 USB 바코드 스캐너로 스캔한 뒤 `Enter`를 입력하면 검사가 시작됩니다.

화면의 `검사 시작` 버튼을 눌러도 같은 방식으로 시작됩니다.

### 바코드 스캐너 사용

USB 바코드 스캐너가 키보드 입력 방식으로 동작하면 스캔한 바코드가 입력창에 자동으로 입력됩니다.

스캐너가 바코드 입력 후 `Enter`까지 자동으로 전송하도록 설정되어 있으면, 별도 버튼을 누르지 않아도 다음 순서로 검사가 시작됩니다.

```text
바코드 스캔
→ 바코드 번호 자동 입력
→ Enter 자동 입력
→ 영상 녹화 시작
→ 실시간 검사 시작
```

스캐너가 `Enter`를 자동 전송하지 않는 경우에는 스캔 후 직접 `Enter`를 누르거나 `검사 시작` 버튼을 눌러야 합니다.

### 검사 진행 중 다른 바코드 입력

검사가 끝나기 전에 다른 바코드가 입력되면 현재 검사를 종료하고 다음 검사를 시작할지 확인합니다.

기존 검사를 종료하는 경우 완료되지 않은 단계는 `MISSING`으로 기록됩니다.

화면에서는 해당 결과를 NG로 표시하지만, 저장되는 JSON의 `final_status` 값은 `REVIEW`입니다.

### 강제 종료

화면 아래의 `현재 박스 강제 종료` 버튼을 누르면 진행 중인 검사를 종료할 수 있습니다.

완료되지 않은 항목은 다음과 같이 저장됩니다.

```text
단계 상태: MISSING
최종 JSON 상태: REVIEW
```

## 저장 영상 검사 실행

저장 영상 검사는 다음 파일로 실행할 수 있습니다.

```bat
run_saved_video.bat
```

또는 가상환경의 Python으로 직접 실행합니다.

```bat
.venv\Scripts\python.exe saved_video_check.py
```

실시간 검사 프로그램 하단의 `저장 영상 검사` 버튼을 통해서도 실행할 수 있습니다.

카메라 영상이 화면에서 크게 표시되면 버튼이나 체크리스트가 화면 아래로 밀려 보이지 않을 수 있습니다. 이 경우 `run_saved_video.bat`을 직접 실행하면 됩니다.

검사 가능한 영상 형식은 다음과 같습니다.

```text
.mp4
.avi
.mov
.mkv
```

검사 순서는 다음과 같습니다.

1. 저장된 영상 파일을 선택합니다.
2. 바코드 또는 제품 번호를 입력합니다.
3. 영상이 재생되면서 17단계 작업 행동을 분석합니다.
4. 단계별 완료 여부와 현재 판정 근거를 표시합니다.
5. 검사 종료 후 JSON 결과를 저장합니다.

원본 영상 파일은 수정하지 않습니다.

분석 중 `Esc`를 누르면 검사를 중단하고 현재까지의 결과를 저장합니다.

모든 단계가 완료되지 않은 경우 완료되지 않은 단계는 `MISSING`, 최종 결과는 `REVIEW`로 기록됩니다.

## 저장 파일

### 실시간 검사

바코드가 `ABC123`인 경우 다음 파일이 생성됩니다.

```text
recordings/ABC123.mp4
results/ABC123_result.json
```

같은 바코드가 다시 사용되면 기존 파일을 덮어쓰지 않도록 날짜와 시간이 파일명에 추가됩니다.

예시:

```text
recordings/ABC123_20260822_204156.mp4
results/ABC123_20260822_204156_result.json
```

### 저장 영상 검사

바코드 또는 제품 번호가 `ABC123`인 경우 다음 결과 파일이 생성됩니다.

```text
results/ABC123_saved_result.json
```

같은 이름의 결과 파일이 이미 존재하면 날짜와 시간이 추가됩니다.

예시:

```text
results/ABC123_20260822_204156_saved_result.json
```

### JSON 결과 내용

결과 파일에는 다음 정보가 포함됩니다.

- 바코드 또는 제품 번호
- 검사 시작 시각
- 검사 종료 시각
- 총 검사 시간
- 검사 영상 경로
- 17개 검사 단계별 결과
- 단계별 `PASS` 또는 `MISSING`
- 단계별 감지 횟수
- 단계별 요구 감지 횟수
- 단계별 완료 시점
- 단계별 판정 근거
- 단계별 신뢰도
- 작업 지연 또는 누락 가능성 경고 내역
- 최종 `PASS` 또는 `REVIEW`

최종 판정 기준은 다음과 같습니다.

```text
PASS   : 전체 17단계 완료
REVIEW : 일부 단계 누락 또는 강제 종료
```

> 실시간 프로그램 화면에서는 완료되지 않은 검사를 NG로 표시하지만, 실제 JSON 결과의 `final_status` 값은 `NG`가 아니라 `REVIEW`입니다.

## 파일 구조

```text
ggoggodack/
├── factory_app.py
├── inspection_engine.py
├── motion_tracker.py
├── armrest_tracker.py
├── saved_video_check.py
├── requirements.txt
├── setup.bat
├── run.bat
├── run_saved_video.bat
├── README.md
├── models/
│   ├── hand_landmarker.task
│   └── pose_landmarker_lite.task
├── recordings/
└── results/
```

각 파일의 역할은 다음과 같습니다.

| 파일 | 역할 |
|---|---|
| `factory_app.py` | 카메라 화면, 바코드 입력, 실시간 검사, 영상 저장, 검사 화면 구성 |
| `inspection_engine.py` | 17단계 검사 순서 정의 및 작업 행동 판정 |
| `motion_tracker.py` | 손, 팔, 손목 및 작업 움직임 추적 보조 |
| `armrest_tracker.py` | 저장 영상 검사에서 암레스트 제품 후보 영역 추적 |
| `saved_video_check.py` | 저장된 영상 선택, 재생 및 사후 검사 |
| `requirements.txt` | 필수 Python 패키지 목록 |
| `setup.bat` | 초기 실행 환경 구성 |
| `run.bat` | 실시간 검사 프로그램 실행 |
| `run_saved_video.bat` | 저장 영상 검사 프로그램 실행 |
| `models/` | MediaPipe 손 및 자세 인식 모델 |
| `recordings/` | 실시간 검사 중 저장된 작업 영상 |
| `results/` | 실시간 검사 및 저장 영상 검사의 JSON 결과 |

## 기본 설정

카메라 설정은 `factory_app.py` 상단에 있습니다.

```python
CAMERA_INDEX = 0
FRAME_WIDTH = 1280
FRAME_HEIGHT = 720
```

다른 카메라가 열리거나 카메라가 연결되지 않으면 `CAMERA_INDEX` 값을 변경합니다.

```python
CAMERA_INDEX = 1
```

필요에 따라 `2`, `3` 등의 값도 확인할 수 있습니다.

검사 시간 설정은 `factory_app.py`와 `saved_video_check.py`에서 검사 엔진을 생성할 때 지정합니다.

```python
InspectionEngine(
    nominal_seconds=70.0,
    warning_seconds=18.0
)
```

- `nominal_seconds`: 전체 작업 시간에 대한 참고 설정값입니다.
- `warning_seconds`: 현재 단계가 확인되지 않을 때 경고하기까지의 시간입니다.

현재 코드에서는 `nominal_seconds`가 전체 작업 시간의 참고값으로 저장되어 있지만, 검사 시간이 70초를 넘었다고 자동으로 종료하거나 불량으로 판정하지는 않습니다.

개별 행동 감지 기준은 `inspection_engine.py`의 다음 함수에 있습니다.

```python
ActionRecognizer.detect()
```

이 함수에서 다음과 같은 기준을 사용합니다.

- 손이 화면에 인식되는 비율
- 양손이 동시에 인식되는 비율
- 손의 전체 이동 거리
- 손의 이동 범위
- 양손 사이 거리 변화
- 주황색 Driver 후보 영역의 크기
- Driver 후보의 이동 거리

현장 검증 없이 기준값을 임의로 낮추면 실제 검사 행동을 하지 않아도 단계가 통과할 수 있습니다.

## 현장 검증 시 확인 사항

1. 카메라 화면에 제품과 작업자의 손이 충분히 보이는지 확인합니다.
2. 바코드 스캐너 입력 후 `Enter`가 자동으로 전송되는지 확인합니다.
3. 바코드 스캔 직후 녹화와 실시간 검사가 동시에 시작되는지 확인합니다.
4. 바코드와 저장 영상 및 JSON 결과 파일명이 일치하는지 확인합니다.
5. 정상 작업에서 검사 진행 상황이 `0/17`부터 `17/17`까지 순서대로 변하는지 확인합니다.
6. 제품 3개에 대한 작업이 각각 구분되어 체크되는지 확인합니다.
7. Driver 검사 단계에서 2회의 확인 동작이 반영되는지 확인합니다.
8. 현재 단계를 의도적으로 수행하지 않았을 때 약 18초 후 경고가 표시되는지 확인합니다.
9. 작업을 강제로 종료했을 때 누락 단계가 `MISSING`으로 저장되는지 확인합니다.
10. 일부 단계가 완료되지 않은 경우 JSON 결과가 `REVIEW`로 저장되는지 확인합니다.
11. 저장된 영상 검사에서도 동일한 17단계가 적용되는지 확인합니다.
12. 조명, 장갑, 작업복, Driver 색상, 카메라 위치가 달라져도 결과가 유지되는지 확인합니다.
13. 작업자가 움직이지 않는데 검사 단계가 자동으로 통과하지 않는지 확인합니다.
14. 실제 정상 작업과 누락 작업 영상을 비교하여 오인식 여부를 검증합니다.

현재 프로그램은 생산 품질을 자동으로 확정하는 시스템이 아니라, 작업자의 검사 절차 수행 여부를 확인하기 위한 보조 도구입니다.
